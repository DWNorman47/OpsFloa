The user's running backlog of everything parked for later lives in **`docs/BACKLOG.md`** (committed on dev). Purpose: one organized reference the user scans to pick what to work on next — "so I can request what I'm interested in addressing."

**How to apply:** when something is deferred, raised-and-parked, suggested, or a user to-do, **file it into `docs/BACKLOG.md`** under the matching section (with the date) rather than only mentioning it in chat. Read the doc when the user asks what's pending/leftover.

Sections: (1) Bugs that can't be addressed until they recur — **do NOT raise these unless they actually reappear**; (2) Bugs set aside for later; (3) Design flaws raised but set aside; (4) Open questions / decisions for the user; (5) Ideas — improvements; (6) Ideas — new features/tools; (7) Planned / ready-to-build (scoped, has a plan); (8) Things the user (David) needs to do; (9) Done / shipped log (landed on dev, newest first).

The **stale project-list bug** is filed under section 1 and must NOT be brought up unless it recurs. Related: [[project_storm_utility_module]], [[project_takeoff_pdf_storage]], [[project_service_call_gaps]], [[project_tool_roadmap]].
