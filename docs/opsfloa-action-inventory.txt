OpsFloA action inventory
Generated: 2026-06-29

Purpose
This file lists the user-facing and admin-facing actions someone could reasonably take in OpsFloA. It is meant to support QA, onboarding design, permission review, help content, and regression testing.

Scope notes
- Some actions are only visible when a module, feature, plan, add-on, or permission is enabled.
- Some actions are public, some require a signed-in user, some require an admin, and some require super admin access.
- This is an application action inventory, not a database schema or formal permission matrix.
- "Company language" settings may rename labels such as project, client, worker, work, or team member in the UI.

Impact tags
- READ: view, search, inspect, preview, download, print, or export data.
- WRITE: create, update, import, upload, submit, approve, reject, archive, restore, or delete data.
- SEND: send email, invite, request, notification, reminder, public link, or external message.
- PUBLIC: visible to signed-out visitors or external users.
- EXTERNAL: touches a third-party service such as QuickBooks, SendGrid, R2, Stripe, Sentry, or a public browser.
- FINANCIAL: touches money, billing, pay, purchase orders, invoices, estimates, or payroll.
- DESTRUCTIVE: deletes, voids, archives, deactivates, cancels, or otherwise removes active use.

22. High-risk flows to test especially carefully

- Clock in, switch project/work, and clock out on mobile PWA.
- Resume mobile PWA after backgrounding without requiring unnecessary login.
- Clock out when projects/work are disabled for a company.
- Admin approval should not allow approving active/unended time entries.
- Public profile and public request can be enabled independently.
- Active public pages should not link to inactive public pages.
- Inventory stock/items table horizontal scrolling should not visually bleed behind frozen columns.
- Inventory column picker should scroll without closing.
- Inventory pagination should not create page-level horizontal scroll.
- Demo Operations seed/refresh should keep dates current without endlessly accumulating notes/photos.
- QuickBooks integration actions should fail clearly when disconnected or not configured.
- Billing checkout/portal should only open for authorized admins.
- Certified payroll routes should require the certified payroll add-on except public classifications where intended.
- Role/permission edits should require role-aware permissions.
- Offline queued writes should not replay under the wrong user/session.

24.3 What is intentionally grouped instead of repeated line by line
- Repeated CRUD patterns are listed once per feature area instead of naming every identical Edit, Save, Cancel, and Delete button on every repeated card.
- Repeated table mechanics are listed once under micro-interactions instead of repeating for every table.
- Repeated validation, loading, empty, disabled, toast, and retry states are listed once under micro-interactions.
- Repeated upload/preview/download/delete media mechanics are listed once globally and then called out in feature areas where they matter.
- Third-party callbacks and webhooks are listed as app/system actions because they are not usually clicked directly by a normal user.
